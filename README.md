# PMIS — AI 智慧監造專案管理資訊系統

> Project Management Information System for AI-Powered Construction Supervision

協助**監造單位**於公共工程執行各階段的資訊化支援平台。系統整合施工各作業流程所需的功能模組，提供一套完整且具延展性的數位管理工具，涵蓋公共工程全生命週期，以提升工程執行效率、履約管控力與管理透明度。

本專案功能設計參考**行政院公共工程委員會 PMIS 推廣版**操作規範，並以「PM 管控」視角重新歸納為 8 大功能模組（PMIS-01 ~ PMIS-08），再疊加 AI 流程優化能力（詳見 [AI 流程優化設計](docs/AI流程優化設計.md)）。

## 各模組功能說明

### PMIS-01 行事曆提醒及預警
以行事曆與儀表板為核心，集中呈現各項具時效性的履約與監造事件，並在期限前主動預警。

- 履約期限、工期里程碑、工期展延核准日期之到期提醒。
- 材料/文件**送審預定日期**、施工查驗**檢驗停留點**、缺失**改善完成期限**之倒數與逾期示警。
- 上級/主管機關查核、會議、首件檢驗等排程提醒。
- 儀表板彙整當日/當月應辦事項數量，支援以年月切換檢視。

### PMIS-02 待辦事項追蹤
追蹤跨單位（監造、施工廠商、二級品管）之待辦與改善辦理情形，確保事事有著落、件件可查。

- 缺失改善（施工品質、安衛、材料不合格）之待辦清單與辦理狀態。
- 送審退件修正、查驗待簽核等流程節點之待處理項目。
- 可即時登錄、依單位/狀態/期限查詢與統計，逾期項目可升級提醒。

### PMIS-03 契約履約管理
建立標案全生命週期的履約起始資料，作為後續材料管控、施工查驗與報表作業的資料基礎（對應官方「標別管理」）。

- **標案基本資料**：契約金額、開工日期、承包商、監造單位等。
- **契約變更資料**：變更次數、變更內容與項目、變更後金額、變更天數。
- **工期里程碑**：關鍵階段性成果與完工日期（可由開工日 + 契約工期自動計算）。
- **工期展延紀錄**：展延名稱、核准日期、核准文號與說明。
- 罰則與付款節點與履約期限連動，供逾期扣款與計價管控。

### PMIS-04 時程進度管理
以預定/實際進度對比呈現工程時程，落後即預警，並支援行動裝置隨時查詢。

- 分項工程進度百分比、預定 vs 實際、S 曲線。
- 里程碑達成度與關鍵路徑影響追蹤。
- 落後預警與行動裝置（手機/平板）進度查詢。

### PMIS-05 環安衛管理
記錄環境、職業安全衛生與交通維持之督導與稽核資料，符合法令及契約規定（對應官方查驗紀錄之「安衛/環保檢查」）。

- 定期與不定期安衛/環保巡檢：高風險作業防護、機具設備安全、防墜與臨邊防護、作業環境衛生、廢棄物與污水、粉塵與噪音等。
- 現場施工抽查**先查驗安衛項目、再查驗施工品質**。
- 稽核紀錄含檢查日期、地點、抽查項目、缺失情形、改善期限與追蹤結果，並可附現場照片與 GPS 座標。
- 重大缺失可即時管制或暫停作業。

### PMIS-06 送審文件材料管理
管控設計、施工、材料設備與試驗報告之送審流程，嚴格追蹤送審狀態與退件修正（對應官方「材料管控」）。

- **材料檢試**：抽驗管理標準表、送審管制總表（表 5-1）、檢(試)驗管制總表（表 5-2）。
- 支援 Excel/範本**批次匯入**建置材料資料庫，減少逐筆建檔。
- **送審文件建立**：勾選施工廠商資料、型錄、試驗報告、樣品，記錄預定/實際送審日期、審查日期與結果。
- **材料取樣**：與材料檢試模組串聯，現場抽驗/取樣、監造簽名、取樣照片上傳。
- **材試不合格追蹤**：不合格自動列管於「不合格追蹤管制表」，通知廠商退料與矯正預防。

### PMIS-07 品質稽核管理
標準化施工查驗流程，管控施工品質抽查、材料設備抽驗與缺失改善成果（對應官方「施工查驗」與「查驗統計」）。

- **查驗申請**：施工廠商依構造物分類提出檢查申請，上傳施工抽查表與核定圖面；支援申請單 Excel/JSON/XML 匯入匯出（相容工程會 CMIS 格式）。
- **查驗填報**：狀態分為未查驗、查驗中、待簽核、已簽核；現場抽查填報結果並記錄 GPS 定位。
- **不合格追蹤**：上傳缺失改善前/中/後照片與文字說明，設定缺失類型與預定改善日期，複查合格後由監造工程師與監造主管**數位簽章**簽核。
- 主管簽核後鎖定為唯讀並自動產生歸檔紀錄，可匯出 PDF/WORD/ODT 查驗表單。
- **查驗統計**：依年月統計查驗與缺失數量（安衛缺失、環保缺失、材料會同檢驗成果）。

### PMIS-08 文件/照片/影片資料庫
集中保存工程監造全程之數位紀錄，支援雲端查詢與持續更新，落實無紙化與資料治理。

- 施工紀錄、材料取樣試驗、安衛環保、業主指示、上級/主管機關稽查、首件檢驗導讀等紀錄。
- 工程照片、影片、圖檔、掃描文件與試驗報告之上傳、預覽與歸檔編號管理。
- **監造報表（監造日報）**：每日填報按圖施工概況、材料管理、人機管理、取樣試驗與重要事項；
  文字敘述可由當日查驗／缺失紀錄一鍵帶入，**數量表則是施工數量與進度的來源**（見下方〈監造日報為單一真實來源〉）。
- 建物歷程檢索（依構造物分類彙整抽查資料）、空間使用量統計，作為數位轉型量化佐證。

## 資料模型

資料模型依 8 大模組設計，以 **Project** 為核心串聯：

- **PMIS-03 契約履約**：`Project`、`ContractChange`（契約變更）、`Milestone`（里程碑/展延）、`PaymentNode`（付款節點）
- **PMIS-04 時程進度**：`WorkItem`（分項工程；**預定**起訖與契約數量為主，
  實際完成量與進度改由監造日報推導 —— `progress` 欄位僅為未計量工項的人工填報值）
- **PMIS-07 品質稽核**：`Inspection`（查驗）、`Defect`（缺失）
- **PMIS-01 行事曆**：`ReminderEvent`（提醒/預警）
- **PMIS-02 待辦**：`TodoItem`（跨單位待辦）
- **PMIS-05 環安衛**：`EhsAudit`（安衛/環保/交通稽核）
- **PMIS-06 送審**：`Submittal`（送審與退件）
- **PMIS-08 資料庫**：`MediaAsset`（照片/影片/文件）、`SupervisionReport`（監造日報）、
  `SupervisionReportItem`（日報數量表）、`GeneratedReport`（彙整報表留存）、
  `SupervisionReportAuditLog`（日報變更軌跡）
  > 監造日報雖存放於本模組，其數量表同時是 PMIS-04 進度與估驗金額的來源，
  > 職責跨越兩個模組，見〈監造日報為單一真實來源〉。

Schema 定義於 `prisma/schema.prisma`，資料庫連線設定於 `prisma.config.ts`。

### 監造日報為單一真實來源

施工數量與進度的資料流方向是**日報 → 台帳／月報**，而非反過來：

```
監造日報數量表 (SupervisionReportItem.dailyQty)
        ↓  僅計入已提送／已核備者
累計完成量 = WorkItem.completedQty（期初基準）+ Σ dailyQty
        ↓
估驗台帳金額、完成率、估驗狀態
工項有效進度 → S 曲線、履約事項上捲
監造月報 3.3 的本期／累計完成
```

由此衍生的幾項約定：

- `WorkItem.completedQty` 是**期初累計基準**，非當前累計；台帳不提供人工編輯。
- `WorkItem.progress` 是**人工填報進度**，僅作為未計量工項（無契約數量）的唯一來源；
  已計量工項的進度由數量推導，且推導值**不回寫**欄位。
- 月報的預定與完成進度採**工程分項基準**（權重＝預定工期天數，預定依起訖線性展開），
  與日報的「當日預定進度」同基準。履約事項的加權達成度（`rolledUpProgress`）
  仍用於專案列表、總覽與儀表板，兩者用途不同、數值不相等。
- 工項單位一旦被日報引用即不可變更，避免新舊紀錄量綱不一致。
- 彙整報表產出即留存（`GeneratedReport`），經人工確認後內容凍結，作為送審依據。

設計脈絡與決策紀錄見 `docs/日報月報計劃整合檢視.md`。

## 快速開始

```bash
npm install          # 安裝套件
npm run db:migrate   # 建立資料庫與資料表
npm run db:seed      # 匯入範例資料
npm run dev          # 啟動開發伺服器
```

開啟 http://localhost:3000 即可看到儀表板。

## 分層架構

專案採單向分層，禁止跨層存取:

```
頁面 / 元件 / server actions
        ↓ 只能呼叫
     service（商業邏輯）
        ↓ 只能呼叫
   repository（唯一能操作 DB）
        ↓
     Prisma / SQLite
```

| 目錄 | 職責 | 規則 |
| --- | --- | --- |
| `src/constant` | 常數（列舉標籤/樣式、行事曆設定等） | 無副作用 |
| `src/lib` | 通用函式庫（`cn`、日期/金額格式化） | 與領域無關 |
| `src/repository` | 所有 DB 操作邏輯 | **只有 repository 可操作 DB**；Prisma client 僅於 `repository/client.ts` 實例化 |
| `src/service` | 服務商業邏輯（驗證、彙整、組合） | **只有 service 可呼叫 repository**；不得直接碰 DB |
| `src/app`、`src/components` | 畫面與互動 | 只呼叫 service，不得引用 repository 或 Prisma |

## AI 助理（Gemini）

畫面最右側的 AI 對話面板串接 Google Gemini API。於 `.env` 填入金鑰即可啟用：

```
AI_KEY="你的 Gemini API 金鑰"
AI_MODEL="gemini-2.5-flash"   # 可選，預設 gemini-2.5-flash
```

流程為 `AiPanel（前端）` → `/api/chat（route handler）` → `service/ai.service.ts` → Gemini。金鑰僅在伺服器端讀取，不會外洩到瀏覽器。未設定 `AI_KEY` 時，面板會回覆提示訊息。

## 資料庫設定

預設使用本機 SQLite（`.env` 中 `DATABASE_URL="file:./prisma/dev.db"`）。改用 PostgreSQL/MySQL 時，調整 `prisma/schema.prisma` 的 `datasource` provider、更換對應 driver adapter 並更新 `.env`。
