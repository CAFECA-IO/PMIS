# 四種自訂圖表整合計劃

> 目標：將 isunfa 的四種自訂圖表（矩陣圖、龍捲風圖、直方圖、箱型圖）整合進 PMIS 專案。
> 日期：2026-08-03

## 已確認的取向

| 項目     | 決定                                               |
| -------- | -------------------------------------------------- |
| 原碼來源 | 把 isunfa 資料夾連進工作區，參考其元件實作         |
| 實作風格 | 沿用 PMIS 純 SVG、零第三方相依、伺服器端渲染       |
| 資料串接 | 先做通用元件 + 範例資料，之後再接真實 service 資料 |

## 技術定位

PMIS 現有圖表（`src/components/charts.tsx`、`src/components/s-curve-chart.tsx`）的模式為：

- 匯出的純函式元件，型別化 props
- 以 `viewBox` 做 RWD 的手刻 SVG
- 顏色用 CSS 變數（如 `var(--primary)`）與 `src/constant/pmis.ts` 的色彩常數
- 伺服器端渲染，無 `"use client"`、零相依

四張新圖將完全比照此模式，維持一致性與最小體積。

### 重要權衡：互動性

純 SVG SSR 元件**無法做 hover tooltip / 動態互動**（需 client JS）。預設先做**靜態版**（標籤直接畫在 SVG 上）；若需要滑鼠提示或動態分箱，再將**該張圖**單獨升級為 `"use client"` 互動版（Phase 5 處理）。

## Phase 1 — 分析與規格

- 讀 isunfa 四個元件原碼
- 逐圖整理：輸入資料模型、視覺元素清單、互動行為
- 對照 PMIS 色彩常數（`src/constant/pmis.ts`）與 SVG 慣例
- 產出「移植規格對照表」
- 決定每張圖在 PMIS 的預期用途，據以設計 props 型別：
  - 矩陣圖 → 風險 / 品質矩陣
  - 龍捲風圖 → 財務 / 碳排敏感度
  - 直方圖 → 量測分布
  - 箱型圖 → 統計離散度

## Phase 2 — 共用基礎

在 `charts.tsx`（或新增 `chart-primitives.tsx`）抽出四圖共用工具：

- 線性比例尺（`scaleLinear`）
- 座標軸與格線元件
- 圖例元件
- 數字 / 日期格式化

避免四支檔案各寫一份重複邏輯。

## Phase 3 — 逐一實作四張圖

比照 `s-curve-chart.tsx` 的「一圖一檔」慣例，新增四個純 SVG 元件，各自附型別與空資料 fallback：

| 檔案                  | 圖表     | 重點                         |
| --------------------- | -------- | ---------------------------- |
| `matrix-chart.tsx`    | 矩陣圖   | 如 5×5 風險機率 / 嚴重度熱區 |
| `tornado-chart.tsx`   | 龍捲風圖 | 雙向水平長條，依影響幅度排序 |
| `histogram-chart.tsx` | 直方圖   | 分箱 + 頻率長條，含分箱邏輯  |
| `box-plot-chart.tsx`  | 箱型圖   | 四分位、鬚線、離群點         |

## Phase 4 — Demo Gallery 頁

- 新增展示頁（例如 `src/app/docs` 底下或獨立 `charts-demo` 路由）
- 用寫死的範例資料排出四張圖，可立即在瀏覽器檢視
- 範例資料集中放一個檔，方便日後替換為真實 service 資料

## Phase 5 — 驗證

- 跑 `npm run build`（含 `prisma generate` + lint）與 `npm run test`，確認無破壞
- 用瀏覽器截圖檢視四張圖的渲染與 RWD
- 檢查 a11y（`role="img"` + `aria-label`，比照現有圖表）
- 若確認需要互動提示，將對應圖升級為 client 互動版

## 風險與變數

- 主要工作量變數在 isunfa 原圖的複雜度，尤其箱型圖離群點與龍捲風排序邏輯
- 純 SVG 靜態版與互動需求之間可能需要二次取捨
- 範例資料的 props 型別需與未來真實 service 資料相容，設計時預留欄位
