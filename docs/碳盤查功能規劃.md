> 版本 v0.2｜對應 PMIS 智慧監造管理系統

## 0. 決策更新（v0.2）

依確認事項調整設計如下：

1. **排放係數採環境部完整版與本年度，且多版本並存可切換**：新增 `EmissionFactorSet`（版本集：名稱、版本號、年度、GWP 集、來源、`isDefault`）。`EmissionFactor` 隸屬某版本集與某類別（`@@unique([setId, categoryId])`）。每份 `CarbonInventory` 以 `factorSetId` 指定採用之版本，可跨年度／版本切換；歷史記錄仍保留 `factorValue` 快照。seed 內建 2026（預設）與 2024 兩版本示範切換。
2. **排放強度指標分母可切換，預設契約金額**：`CarbonInventory.intensityBasis`（`CONTRACT_AMOUNT` 預設／`FLOOR_AREA`／`DURATION`）。為支援樓地板面積基準，`Project` 新增 `floorArea`。
3. **第三方查證狀態流與稽核軌跡**：`CarbonEntry` 保留 `DRAFT→CONFIRMED→VERIFIED` 狀態並新增 `verifiedById`／`verifiedAt`；`CarbonInventory` 增 `verifier`／`verifiedAt`；新增 `CarbonAuditLog`（動作、操作者、狀態變更、時間）記錄完整稽核軌跡。
4. **費思自動擷取憑證納入第一版**：`CarbonEntry.aiExtracted` 標記由費思自憑證擷取之草稿；擷取流程（上傳電費單／發票 → 回填活動量草稿）列入 v1 範圍（見 §10 階段五提前）。

## 1. 目標與依據

在既有 PMIS 中新增一個「碳盤查」模組，讓監造與專案團隊能以工程專案為單位，記錄各類活動數據、套用排放係數，自動計算溫室氣體排放量（以 tCO₂e 表示），並產出可供查證與申報的盤查清冊與報表。

方法學對齊下列國際與國內框架：

- **GHG Protocol** 的範疇分類（Scope 1／2／3）。
- **ISO 14064-1** 組織型溫室氣體盤查的邊界界定、量化與報告要求。
- 台灣行政院環境部（原環保署）**溫室氣體排放係數管理表** 作為預設排放係數來源；電力係數採用能源署／台電公告之**電力排碳係數**。
- GWP（全球暖化潛勢）採 IPCC AR5／AR6（以係數庫版本欄位控管，可切換）。

> 註：排放係數會逐年更新，且台灣申報版本可能與國際版本不同。係數庫需保留「版本／年度／來源」欄位，並在此規劃預留切換能力（見 §5）。實作前建議再確認採用的係數版本年度。

## 2. 盤查邊界與排放源分類

以「工程專案」為盤查邊界（organizational boundary = 單一專案），依 GHG Protocol 分為四類（第四類為方便工地實務而獨立）：

| 範疇 | 說明 | 營建工地常見排放源 |
| --- | --- | --- |
| Scope 1 直接排放 | 專案直接控制之燃料燃燒與逸散 | 施工機具柴油、工程車輛燃油、發電機、動火作業、乙炔/瓦斯、滅火器/冷媒逸散 |
| Scope 2 外購電力 | 外購電力之間接排放 | 工地臨時用電、辦公/工務所用電 |
| Scope 3 上下游 | 價值鏈間接排放 | 建材含碳（混凝土、鋼筋、瀝青、水泥）、材料運輸、營建廢棄物處理、外包分包、員工通勤 |
| 用水及其他 | 非 GHG Protocol 必要但工地常追蹤 | 自來水、外購蒸氣、其他 |

每一筆排放記錄需能標記其**範疇**與**排放源類別**，以支援分範疇彙總與 ISO 14064-1 報告。

## 3. 計算方法

核心公式：

```
排放量 (tCO₂e) = 活動數據 (activity data) × 排放係數 (emission factor) × GWP 調整
```

- **活動數據**：如柴油公升數、用電度數（kWh）、混凝土立方公尺、鋼筋公噸、運輸噸公里。
- **排放係數**：由係數庫依「排放源類別 + 單位 + 版本」查得，單位如 kgCO₂e/L、kgCO₂e/kWh、kgCO₂e/m³。
- **單位換算**：係數庫內以基準單位存放；輸入端允許常用單位並在服務層換算。
- **結果**：以 kgCO₂e 計算、tCO₂e 呈現（除以 1000），四捨五入至小數點後精度可設定。

計算集中在 service 層（例如 `carbon.service.computeEntryEmission()` 與 `computeInventorySummary()`），沿用現有 `computeMilestoneProgress` / `computeProjectOverview` 的純函式模式，方便測試與在總覽頁重用。

## 4. 資料模型（Prisma）

沿用現有慣例：`cuid` 主鍵、`Decimal` 金額/數量、`createdAt/updatedAt`、軟刪除 `deletedAt`、以 `projectId` 關聯 `Project` 並 `onDelete: Cascade`。

新增列舉：

```prisma
enum CarbonScope {
  SCOPE_1   // 直接排放
  SCOPE_2   // 外購電力
  SCOPE_3   // 上下游
  OTHER     // 用水及其他
}

enum CarbonEntryStatus {
  DRAFT      // 草稿
  CONFIRMED  // 已確認
  VERIFIED   // 已查證
}
```

四個主要模型：

```prisma
/// 單一專案的一次盤查（可依年度/期別分次）
model CarbonInventory {
  id           String        @id @default(cuid())
  projectId    String
  name         String        // 如「2026 年度盤查」
  periodStart  DateTime?
  periodEnd    DateTime?
  baselineCo2e Decimal?      // 基準值 (tCO₂e)
  targetCo2e   Decimal?      // 減量目標 (tCO₂e)
  note         String?
  createdAt    DateTime      @default(now())
  updatedAt    DateTime      @updatedAt
  deletedAt    DateTime?

  project Project        @relation(fields: [projectId], references: [id], onDelete: Cascade)
  entries CarbonEntry[]

  @@index([projectId])
}

/// 單筆活動數據記錄
model CarbonEntry {
  id          String            @id @default(cuid())
  inventoryId String
  scope       CarbonScope
  categoryId  String            // 排放源類別
  factorId    String?           // 使用之排放係數（快照 factorValue 以防日後係數更動）
  workItemId  String?           // 可選：關聯分項工程
  activityQty Decimal           // 活動數據數量
  activityUnit String           // 輸入單位（如 L、kWh、m³、t）
  factorValue Decimal           // 計算當下的排放係數快照 (kgCO₂e/unit)
  co2e        Decimal           // 計算結果 (kgCO₂e)
  status      CarbonEntryStatus @default(DRAFT)
  occurredAt  DateTime?         // 活動發生日
  evidenceUrl String?           // 憑證/發票連結（可接 storage）
  note        String?
  createdBy   String?
  createdAt   DateTime          @default(now())
  updatedAt   DateTime          @updatedAt
  deletedAt   DateTime?

  inventory CarbonInventory     @relation(fields: [inventoryId], references: [id], onDelete: Cascade)
  category  EmissionCategory    @relation(fields: [categoryId], references: [id])
  factor    EmissionFactor?     @relation(fields: [factorId], references: [id])
  workItem  WorkItem?           @relation(fields: [workItemId], references: [id], onDelete: SetNull)

  @@index([inventoryId])
  @@index([scope])
}

/// 排放源類別（如：柴油、外購電力、卜特蘭水泥）
model EmissionCategory {
  id        String      @id @default(cuid())
  scope     CarbonScope
  name      String
  unit      String      // 基準單位
  active    Boolean     @default(true)

  factors EmissionFactor[]
  entries CarbonEntry[]
}

/// 排放係數（含版本控管）
model EmissionFactor {
  id         String   @id @default(cuid())
  categoryId String
  value      Decimal  // kgCO₂e / unit
  unit       String
  source     String   // 如「環境部排放係數管理表 6.0.4」
  year       Int      // 適用年度
  gwpSet     String   // 如「AR5」
  createdAt  DateTime @default(now())

  category EmissionCategory @relation(fields: [categoryId], references: [id])
  entries  CarbonEntry[]

  @@index([categoryId])
}
```

在 `Project` 加上 `carbonInventories CarbonInventory[]`，並在 `WorkItem` 加上 `carbonEntries CarbonEntry[]`（供分項工程層級歸屬）。

**設計重點**：`CarbonEntry.factorValue` 為計算當下的係數快照，即使日後係數庫更新，歷史盤查結果仍可追溯、可查證。

## 5. 排放係數庫（Emission Factor Library）

以 `EmissionCategory` + `EmissionFactor` 建立可維護的係數庫，seed 提供常用預設值（示意，實作前需以官方最新版本校正）：

| 範疇 | 類別 | 基準單位 | 係數（示意） | 來源 |
| --- | --- | --- | --- | --- |
| Scope 1 | 柴油 | L | 2.6 kgCO₂e/L | 環境部排放係數表 |
| Scope 1 | 汽油 | L | 2.3 kgCO₂e/L | 環境部排放係數表 |
| Scope 2 | 外購電力 | kWh | 0.494 kgCO₂e/kWh | 電力排碳係數（年度更新） |
| Scope 3 | 常態混凝土 | m³ | 依配比 | 環境產品宣告 EPD／文獻 |
| Scope 3 | 鋼筋 | t | 依來源 | EPD／文獻 |
| 其他 | 自來水 | m³ | 0.15 kgCO₂e/m³ | 自來水公司 |

版本控管：同一類別可有多個 `EmissionFactor`（不同 `year`/`source`/`gwpSet`）；新增 `CarbonEntry` 時預設帶入該類別最新適用版本，使用者可覆寫。

## 6. 頁面與 UX

採「獨立模組 + 專案分頁」雙入口（最完整），沿用現有 shadcn 風格、Card/Badge/Table、`ProgressWithTarget`、`RadialGauge` 與 S 曲線元件。

### 6.1 獨立模組 `/carbon`（跨專案彙總，PMIS-10）
側邊欄新增「碳盤查」項目（Leaf/Factory 類圖示）。內容：

- 頂部 KPI：可視專案總排放 tCO₂e、較基準增減、達標進度、各範疇占比。
- 範疇占比圖（Scope 1/2/3/其他）＋各專案排放排行（BarList）。
- 專案清單表：每案累計排放、強度（tCO₂e/契約金額或/樓地板面積）、對比目標。
- 依現有權限：ADMIN/MANAGER 看全部，其他人只看被指派專案（沿用 `listProjects` 範圍邏輯）。

### 6.2 專案內分頁「碳盤查」
在 `/projects/[id]` 的 tab 列新增 `carbon`（置於「相關作業」附近）：

- 盤查總覽：本案累計排放、分範疇堆疊、對比基準/目標的 `ProgressWithTarget`、月別排放趨勢（重用 S 曲線）。
- 活動數據明細表：範疇、類別、活動量×係數=排放、狀態（草稿/已確認/已查證）、憑證連結。
- 新增/編輯表單：選範疇 → 類別（連動係數）→ 輸入活動量與單位 → 即時試算 tCO₂e；可上傳/連結憑證。
- 沿用軟刪除 + 復原（`RecordDeleteButton`）。

## 8. 報表與匯出

- **盤查清冊**：依範疇/類別彙總，含活動量、係數、係數來源版本、排放量，供 ISO 14064-1 附件。
- **報告書骨架**：邊界說明、方法學、係數來源、分範疇結果、基準與目標對比、減量措施。
- **匯出**：CSV（明細）、PDF（報表）；可沿用 xlsx/pdf 產製流程。
- **查證軌跡**：每筆記錄狀態（草稿→已確認→已查證）與係數快照，支援第三方查證。

## 10. 實作階段規劃

1. **階段一 — 資料層**：Prisma 新增 4 模型 + 2 列舉、`db push`/`generate`、係數庫 seed。
2. **階段二 — 服務/倉儲**：`carbon.repository`、`carbon.service`（計算、彙總、範圍過濾）、單元測試計算邏輯。

4. **階段四 — 獨立模組 `/carbon`**：跨專案 KPI 與排行、側邊欄項目。

## 12. 風險與注意事項

- **係數準確性**：Scope 3 建材含碳變異大，建議標註資料品質（實測/EPD/文獻預設）。
- **資料完整性**：盤查結果高度依賴活動數據齊全度，需以「待確認筆數」提醒。
- **版本可追溯**：務必保留係數快照，避免回溯計算失真。
- **非財務數據**：碳排數據非決策唯一依據，正式申報仍須由專責人員與查證機構確認。
